### 业务规则与边界条件

#### 任务创建与修改校验链

按优先级依次校验：

1. **@Validated 注解校验**：jobName 非空且≤64字符、invokeTarget 非空且≤1000字符、cronExpression 非空且≤255字符
2. **Cron 表达式有效性**：`CronUtils.isValid()` 必须返回 true
3. **禁止 RMI 调用**：invokeTarget 不允许包含 `rmi:`
4. **禁止 LDAP 调用**：invokeTarget 不允许包含 `ldap:` 或 `ldaps:`
5. **禁止 HTTP 调用**：invokeTarget 不允许包含 `http:` 或 `https:`
6. **禁止违规字符串**：invokeTarget 不允许包含黑名单中的任一字符串
7. **白名单校验**：invokeTarget 必须通过 `ScheduleUtils.whiteList()` 校验

#### 黑名单（JOB_ERROR_STR）

| 黑名单前缀 | 说明 |
|-----------|------|
| java.net.URL | 禁止网络请求 |
| javax.naming.InitialContext | 禁止JNDI注入 |
| org.yaml.snakeyaml | 禁止YAML解析 |
| org.springframework | 禁止调用Spring框架内部 |
| org.apache | 禁止调用Apache内部 |
| com.ruoyi.common.utils.file | 禁止文件操作 |
| com.ruoyi.common.config | 禁止配置操作 |
| com.ruoyi.generator | 禁止代码生成 |

#### 白名单

- 允许的包名前缀：`com.ruoyi.quartz.task`
- Spring Bean 方式调用时，Bean 的包名必须以白名单前缀开头且不以黑名单前缀开头

#### 其他规则

- **新增任务默认暂停**：新增任务状态强制设为暂停，需手动启用
- **启动时重新加载**：项目启动时清空调度器，从数据库重新加载所有任务
- **不可手动修改数据库ID和任务组名**：否则会导致脏数据
- **立即执行前提**：调度器中必须已存在该 JobKey，否则返回 false
- **任务过期判断**：若 CronUtils.getNextExecution() 返回非 null 才创建调度
- **所有写操作使用事务**：@Transactional(rollbackFor = Exception.class)

#### invokeTarget 调用目标格式

```
# Spring Bean 方式（推荐）
ryTask.ryParams('test')
ryTask.ryNoParams()
ryTask.ryMultipleParams('hello', true, 2000L, 3.14D, 100)

# 完整类名方式
com.ruoyi.quartz.task.RyTask.ryParams('test')
```

参数类型推断规则：

| 格式 | 类型 | 示例 |
|------|------|------|
| 单引号/双引号包裹 | String | `'hello'` |
| true/false | Boolean | `true` |
| 数字+L后缀 | Long | `2000L` |
| 数字+D后缀 | Double | `3.14D` |
| 纯数字 | Integer | `100` |

#### 计划策略（misfirePolicy）

| 值 | 说明 |
|----|------|
| 0 | 默认（Quartz默认处理） |
| 1 | 立即触发执行 |
| 2 | 触发一次执行 |
| 3 | 不触发立即执行 |

#### 并发控制（concurrent）

| 值 | 说明 |
|----|------|
| 0 | 允许并发执行 |
| 1 | 禁止并发执行（使用 @DisallowConcurrentExecution） |

## 新增定时任务的标准流程

1. 在 `com.ruoyi.quartz.task` 包下创建任务类，添加 `@Component("beanName")`
2. 编写任务方法，支持 String/Boolean/Long/Double/Integer 参数类型
3. 在管理后台"定时任务"页面新增任务，填写 invokeTarget（如 `beanName.methodName('param')`）
4. 设置 Cron 表达式和执行策略
5. 新增后任务默认暂停，手动启用后开始调度

示例任务类：

```java
@Component("myTask")
public class MyTask {
    public void myParams(String params) {
        System.out.println("执行任务: " + params);
    }

    public void myNoParams() {
        System.out.println("执行无参任务");
    }
}
```

对应 invokeTarget：`myTask.myParams('hello')` 或 `myTask.myNoParams()`

## 已知限制与注意事项

- **不可手动修改数据库ID和任务组名**：直接修改 sys_job 表的 job_id 或 job_group 会导致调度器脏数据，必须通过系统接口操作
- **新增任务默认暂停**：新增任务状态强制设为暂停，需手动启用后才会开始调度
- **启动时重新加载**：项目启动时清空调度器并从数据库重新加载所有任务，运行时通过API创建的临时任务（非数据库任务）会丢失
- **立即执行前提**：立即执行要求调度器中已存在该 JobKey，若任务已过期或未创建调度则返回 false
- **invokeTarget安全限制**：调用目标字符串受白名单和黑名单双重限制，禁止调用 RMI/LDAP/HTTP 协议，禁止调用文件操作、配置、代码生成等敏感包
- **参数类型限制**：仅支持 String/Boolean/Long/Double/Integer 五种参数类型，其他类型无法解析
- **并发控制**：concurrent=1（禁止并发）使用 @DisallowConcurrentExecution 实现，同一任务上一次执行未完成时不会触发下一次
- **任务过期处理**：misfirePolicy 控制错过触发时间的处理策略，默认为0（Quartz默认处理）
- **调度日志自动记录**：任务执行后自动记录日志，无需手动调用，日志包含开始/结束时间和异常信息
- **日志清空不可恢复**：clean 接口清空全部调度日志，不可恢复
- **Cron表达式校验**：新增和修改任务时必须校验Cron表达式有效性，可通过 /monitor/job/checkCronExpressionIsValid 接口校验
