### 认证流程

**认证入口**：[UserRealm.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/shiro/realm/UserRealm.java) → [SysLoginService.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/shiro/service/SysLoginService.java)

1. 用户提交用户名+密码+验证码
2. 验证码校验（captchaValidate 过滤器）
3. SysLoginService.login() 执行认证：
   - 验证码校验 → CaptchaException
   - 用户名查询 → UserNotExistsException
   - 密码校验 → UserPasswordNotMatchException
   - 密码重试超限 → UserPasswordRetryLimitExceedException
   - 用户被禁用 → UserBlockedException
   - 角色被禁用 → RoleBlockedException
4. 认证成功后更新登录IP和时间

### 授权流程

**授权入口**：UserRealm.doGetAuthorizationInfo()

- **管理员**：添加 "admin" 角色 + `*:*:*` 全权限
- **普通用户**：从数据库查询角色集合 + 菜单权限集合

### @Anonymous 注解

标记在 Controller 方法上，表示该接口无需登录即可访问。ShiroConfig 启动时扫描所有 @Anonymous 注解，将对应 URL 加入匿名访问列表。

## 二、密码策略

**核心类**：[SysPasswordService.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/shiro/service/SysPasswordService.java)

### 加密算法

```
加密后密码 = Md5Utils.hash(loginName + password + salt)
```

- 使用 MD5 加盐加密
- salt 为随机生成的字符串，存储在 sys_user 表的 salt 字段
- 密码和 salt 在 SysUser 中标记 @JsonIgnore，不会序列化到前端

### 密码重试限制

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| user.password.maxRetryCount | 最大重试次数 | 5 |

- 使用 EhCache 缓存（`loginRecordCache`）记录每个用户名的重试次数
- 超过最大重试次数后抛出 UserPasswordRetryLimitExceedException，账户锁定10分钟
- 登录成功后清除重试计数缓存
- 管理员可通过"登录日志"页面的"账户解锁"功能手动解锁

## 三、数据权限

**核心类**：[DataScopeAspect.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/aspectj/DataScopeAspect.java)

### 使用方式

在 Service 方法上添加 `@DataScope` 注解：

```java
@DataScope(deptAlias = "d", userAlias = "u")
public List<SysUser> selectUserList(SysUser user) { ... }
```

### 注解参数

| 参数 | 说明 |
|------|------|
| deptAlias | 部门表的别名 |
| userAlias | 用户表的别名 |
| permission | 权限字符（默认空，不限制） |

### 过滤规则

| dataScope值 | 名称 | SQL条件 |
|-------------|------|---------|
| 1 | 全部数据 | 无限制（清空SQL条件） |
| 2 | 自定义数据 | `dept_id IN (SELECT dept_id FROM sys_role_dept WHERE role_id = ?)` |
| 3 | 本部门数据 | `dept_id = 用户部门ID` |
| 4 | 本部门及以下 | `dept_id IN (SELECT dept_id FROM sys_dept WHERE dept_id = ? or find_in_set(?, ancestors))` |
| 5 | 仅本人 | `user_id = 用户ID` |

### 生效条件

1. 方法必须有 `@DataScope` 注解
2. 方法参数必须继承 BaseEntity（params Map 用于存放 dataScope SQL）
3. Mapper XML 中必须引用 `${params.dataScope}`（注意是 `${}` 不是 `#{}`，因为拼接的是SQL片段）
4. 超级管理员（admin）不受数据权限限制
5. 若角色不包含指定权限字符，限制不查询任何数据

### Mapper XML 使用示例

```xml
<select id="selectUserList" resultMap="SysUserResult">
    SELECT u.* FROM sys_user u LEFT JOIN sys_dept d ON u.dept_id = d.dept_id
    WHERE u.del_flag = '0'
    <if test="params.dataScope != null and params.dataScope != ''">
        AND ${params.dataScope}
    </if>
</select>
```

## 四、操作日志

**核心类**：[LogAspect.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/aspectj/LogAspect.java)

### 使用方式

在 Controller 方法上添加 `@Log` 注解：

```java
@Log(title = "用户管理", businessType = BusinessType.INSERT)
@PostMapping("/add")
public AjaxResult addSave(SysUser user) { ... }
```

### 注解参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| title | 模块标题 | 空 |
| businessType | 业务类型 | OTHER |
| operatorType | 操作类别 | MANAGE |
| isSaveRequestData | 是否保存请求参数 | true |
| isSaveResponseData | 是否保存响应结果 | true |
| excludeParamNames | 排除的请求参数名 | 空 |

### businessType 枚举

| 值 | 说明 |
|----|------|
| OTHER | 其它 |
| INSERT | 新增 |
| UPDATE | 修改 |
| DELETE | 删除 |
| GRANT | 授权 |
| EXPORT | 导出 |
| IMPORT | 导入 |
| FORCE | 强退 |
| GENCODE | 生成代码 |
| CLEAN | 清空 |

### 记录内容

| 字段 | 来源 |
|------|------|
| 操作人 | 当前登录用户 loginName |
| 部门名称 | 当前用户部门 |
| 请求URL | request.getRequestURI() |
| 请求IP | IpUtils.getIpAddr() |
| 请求方式 | request.getMethod() |
| 方法名 | 类名.方法名() |
| 请求参数 | request.getParameterMap()，排除 password 等敏感字段，截取前2000字符 |
| 响应结果 | 方法返回值，截取前2000字符 |
| 异常信息 | 异常堆栈，截取前2000字符 |
| 消耗时间 | 方法执行耗时（毫秒） |

### 敏感字段排除

自动排除以下字段不记录到 oper_param：password、oldPassword、newPassword、confirmPassword

### 异步写入

通过 AsyncManager 异步写入 sys_oper_log 表，不阻塞业务方法执行。

## 五、防重提交

**核心类**：[SameUrlDataInterceptor.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/interceptor/impl/SameUrlDataInterceptor.java)

### 使用方式

在 Controller 方法上添加 `@RepeatSubmit` 注解：

```java
@RepeatSubmit(interval = 10000)  // 10秒内不允许重复提交
@PostMapping("/add")
public AjaxResult addSave(SysUser user) { ... }
```

### 注解参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| interval | 间隔时间(毫秒) | 5000（5秒） |

### 判断逻辑

同时满足以下两个条件则判定为重复提交：

1. **参数相同**：当前请求参数与上次请求参数完全相同
2. **时间间隔不足**：两次请求间隔时间 < interval 配置值

### 实现方式

- 以请求URL为key，将请求参数和时间戳存入 Session
- Session key 为 `repeatData`
- 每次请求先从 Session 取上次数据对比，非重复则更新 Session 数据

## 六、XSS防护

**核心类**：[XssFilter.java](../../ruoyi-common/src/main/java/com/ruoyi/common/xss/XssFilter.java)、[XssValidator.java](../../ruoyi-common/src/main/java/com/ruoyi/common/xss/XssValidator.java)

### 配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| xss.enabled | XSS过滤开关 | true |
| xss.excludes | 排除URL（逗号分隔） | /system/notice/* |
| xss.urlPatterns | 匹配URL（逗号分隔） | /system/*,/monitor/*,/tool/* |

### 过滤规则

1. **GET/DELETE 请求不过滤**，直接放行
2. **排除URL列表**中的请求不过滤（如通知公告，因为使用富文本编辑器）
3. 其余匹配的 POST/PUT 请求，使用 XssHttpServletRequestWrapper 包装，对请求参数进行 HTML 清洗
4. Domain 字段上加 `@Xss` 注解，在 Bean 校验阶段拦截非法字符

### @Xss 注解

用于 Domain 字段级别的 XSS 校验：

```java
@Xss(message = "包含非法字符")
@NotBlank
@Size(max = 30)
private String loginName;
```

## 八、异常处理

**核心类**：[GlobalExceptionHandler.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/web/exception/GlobalExceptionHandler.java)

### 异常处理映射

| 异常类型 | 处理方式 | 返回 |
|---------|---------|------|
| AuthorizationException | Ajax→AjaxResult.error("没有权限")；非Ajax→error/unauth页面 | 根据请求类型 |
| ServiceException | Ajax→AjaxResult.error(消息)；非Ajax→error/service页面 | 根据请求类型 |

| HttpRequestMethodNotSupportedException | AjaxResult.error(消息) | JSON |
| MissingPathVariableException | AjaxResult.error(格式化消息) | JSON |
| MethodArgumentTypeMismatchException | AjaxResult.error(参数类型不匹配) | JSON |
| BindException | AjaxResult.error(第一个校验错误消息) | JSON |
| RuntimeException | AjaxResult.error(消息) | JSON |
| Exception | AjaxResult.error(消息) | JSON |

### 自定义异常使用

```java
// 业务异常（最常用）
throw new ServiceException("用户名已存在");

// 演示模式异常
throw new DemoModeException();
```

### Ajax/非Ajax判断

通过检查请求头 `X-Requested-With` 是否为 `XMLHttpRequest` 来判断。

## 九、多数据源

**核心类**：[DynamicDataSource.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/datasource/DynamicDataSource.java)、[DataSourceAspect.java](../../ruoyi-framework/src/main/java/com/ruoyi/framework/aspectj/DataSourceAspect.java)

### 使用方式

在 Service 方法或类上添加 `@DataSource` 注解：

```java
@DataSource(DataSourceType.SLAVE)  // 切换到从库
public List<SysUser> selectUserList(SysUser user) { ... }
```

### 切换逻辑

1. DataSourceAspect（@Order(1)，最高优先级）拦截带 @DataSource 的方法
2. 优先取方法级别注解，其次取类级别注解
3. 将数据源标识设置到 DynamicDataSourceContextHolder（ThreadLocal）
4. 执行目标方法
5. finally 中清除数据源标识，恢复默认数据源

### 数据源类型

| 值 | 说明 |
|----|------|
| MASTER | 主库（默认） |
| SLAVE | 从库 |

### 配置

在 application-druid.yml 中配置主从数据源连接信息。

## 十一、缓存

**缓存框架**：EhCache

**配置文件**：`ruoyi-admin/src/main/resources/ehcache/ehcache-shiro.xml`

### 缓存使用场景

| 缓存名称 | 说明 | 刷新时机 |
|---------|------|---------|
| 字典缓存 | sys_dict_data 数据 | 字典增删改后自动刷新 |
| 参数缓存 | sys_config 数据 | 参数增删改后自动刷新 |
| 登录记录缓存 | 密码重试计数 | 登录成功后清除 |
| Shiro缓存 | 认证/授权信息 | 权限变更时清理 |

### 缓存工具类

```java
// 字典缓存
DictUtils.getDictLabel(dictType, dictValue);  // 获取标签
DictUtils.getDictCache(dictType);              // 获取列表
DictUtils.clearDictCache();                    // 清空缓存

// 参数缓存
configService.selectConfigByKey(configKey);    // 自动走缓存

// 通用缓存
CacheUtils.get(cacheName, key);                // 获取
CacheUtils.put(cacheName, key, value);         // 写入
CacheUtils.remove(cacheName, key);             // 删除
```
