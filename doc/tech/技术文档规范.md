# 若依管理系统 技术文档规范

> 版本：v1.0 | 适用项目：RuoYi v4.8.3 | 更新日期：2026-06-18

---

## 一、规范目标

| 受众 | 目标 |
|------|------|
| **产品经理** | 快速理解系统能力边界，判断需求可行性，减少沟通成本 |
| **研发新手** | 快速上手开发，知道改哪里、怎么改、有哪些坑 |
| **AI 助手** | 通过导航索引快速定位代码位置，精准生成或修改代码 |

---

## 二、文档目录结构规范

所有技术文档统一放在项目 `doc/tech/` 目录下，按以下结构组织：

```
doc/tech/
├── README.md                    ← 总导航（必须存在，AI入口）
├── 01-项目概览.md                ← 项目简介、技术栈、模块划分
├── 02-架构设计.md                ← 整体架构、分层、请求流转
├── 03-模块详解/                  ← 每个业务模块一个文件
│   ├── _index.md                ← 模块导航
│   ├── 系统管理.md               ← 用户/角色/菜单/部门/岗位/字典/配置/通知
│   ├── 系统监控.md               ← 在线用户/操作日志/登录日志/服务监控/缓存监控
│   └── 定时任务.md               ← 任务管理/任务日志
├── 04-基础设施.md                ← 安全认证/数据源/缓存/文件上传/XSS防护/异常处理
├── 05-代码生成器.md              ← 代码生成器使用与扩展
├── 06-开发指南.md                ← 新增业务模块的标准流程与规范
└── 07-数据库字典.md              ← 全部表结构与字段说明
```

### 3.4 模块详解（03-模块详解/）

每个业务模块一个文件，**统一遵循以下模板**：

```markdown
# {模块名称}

## 功能清单

| 功能 | 说明 | 权限标识 | 菜单路径 |
|------|------|---------|---------|
| xxx | xxx | system:user:list | 系统管理/用户管理 |

## 代码定位

| 层 | 文件路径 |
|----|---------|
| Controller | ruoyi-admin/.../SysXxxController.java |
| Service接口 | ruoyi-system/.../ISysXxxService.java |
| Service实现 | ruoyi-system/.../SysXxxServiceImpl.java |
| Mapper接口 | ruoyi-system/.../SysXxxMapper.java |
| Mapper XML | ruoyi-system/.../SysXxxMapper.xml |
| Domain | ruoyi-system/.../SysXxx.java 或 ruoyi-common/.../SysXxx.java |
| 列表页面 | templates/system/xxx/xxx.html |
| 新增页面 | templates/system/xxx/add.html |
| 编辑页面 | templates/system/xxx/edit.html |

## 接口清单

| 接口路径 | 方法 | 说明 | 权限标识 | 请求参数 | 返回结构 |
|---------|------|------|---------|---------|---------|

## 业务规则与边界条件

- {规则1}：如"用户名唯一，长度2-20，不允许特殊字符"
- {规则2}：如"删除角色前必须解除与用户的关联"
- {边界1}：如"管理员(admin)不允许删除/停用"
- {边界2}：如"超级管理员角色不允许修改权限"

## 数据模型

### {表名}

| 字段 | 类型 | 必填 | 说明 | 边界/约束 |
|------|------|------|------|----------|

## 关联关系

- 与 XX 模块：{一对多/多对多}，关联字段 xxx

## 已知限制与注意事项

- {限制1}
- {注意1}
```

**关键要求**：
- **业务规则与边界条件**是核心，必须详细列出所有校验规则、不可操作场景、特殊处理逻辑
- **代码定位**必须精确到文件路径，让 AI 和人都能直接找到
- **接口清单**必须含权限标识，产品据此判断功能可用性

## 四、写作规范

### 4.1 语言与格式

| 项目 | 规范 |
|------|------|
| 语言 | 中文 |
| 格式 | Markdown |
| 代码引用 | 使用相对路径链接，如 `[SysUserController](../../ruoyi-admin/src/main/java/com/ruoyi/web/controller/system/SysUserController.java)` |
| 表格优先 | 所有结构化信息用表格，不用大段文字 |
| 代码块 | 必须标注语言类型 |

### 4.2 内容原则

1. **精准**：文件路径、类名、方法名必须与代码完全一致，可复制可定位
2. **边界优先**：边界条件、校验规则、限制说明比正常流程更重要
3. **可操作**：每条说明必须能让读者知道"怎么做"，不只是"是什么"
4. **不重复**：同一信息只在一处详细描述，其他地方引用链接
5. **保持同步**：代码变更时同步更新文档，文档与代码不一致时以代码为准

### 4.3 AI 友好要求

- 总导航必须包含**代码定位速查表**，格式为 `功能 → 文件路径` 的完整链路
- 每个模块详解必须包含**代码定位**章节，精确到每个层的文件路径
- 接口清单必须包含**权限标识**列
- 边界条件必须单独成章，不能混在流程描述中
- 关键类和方法必须标注**完整包路径**

## 五、文档更新机制

| 触发场景 | 更新要求 |
|---------|---------|
| 新增业务模块 | 更新总导航 + 新增模块详解 + 更新数据库字典 |
| 修改接口/字段 | 更新对应模块详解的接口清单和数据模型 |
| 修改业务规则 | 更新对应模块详解的业务规则与边界条件 |
| 修改基础设施配置 | 更新 04-基础设施.md |
| 修改代码生成模板 | 更新 05-代码生成器.md |
| 数据库表变更 | 更新 07-数据库字典.md |

## 六、质量检查清单

文档生成后，逐项检查：

- [ ] 总导航的代码定位速查表是否覆盖所有功能模块
- [ ] 每个模块详解是否包含：功能清单、代码定位、接口清单、业务规则与边界条件、数据模型
- [ ] 边界条件是否完整（不可删除、不可修改、唯一性校验、状态限制等）
- [ ] 文件路径是否与实际代码一致
- [ ] 接口权限标识是否与代码 @RequiresPermissions 一致
- [ ] 数据库字段是否与 Mapper XML 一致
- [ ] 基础设施章节是否覆盖所有通用机制
- [ ] 开发指南是否包含完整的标准流程和代码模板
